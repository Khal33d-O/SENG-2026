# W1.03 document brief and rubric

Submit the workspace's `proposal.json` with your completed response (`description.md`, `review.md`, `approval.md`
and your individual explanation in `evidence.md`). A paragraph named "PR" without the actual base/head, diff, check and
review history does not complete the task.

| Criterion | Meets | Not yet |
|---|---|---|
| Repository boundary | Names configuration as the owner of the notice and cites the README/file | Edits or proposes in application |
| Scope | Compares every changed line with the governing request revision (R1, then R2) | Treats a passing preview as permission |
| Revision-bound evidence | Check head and proposal head compared by full identifier | "Checked change/notice" |
| Review comment | Line-specific observation, effect and bounded action | "Please fix this" / "Looks fine" |
| Correction | New commit, update, fresh check, current approval; earlier records kept | Edited JSON or deleted history |
| Individual explanation | Own initial note, evidence plan, assistance and next revisit | Copies partner's reasoning |
